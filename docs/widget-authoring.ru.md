# Создание виджетов

[English](widget-authoring.md) · [Русский](widget-authoring.ru.md) · [简体中文](widget-authoring.zh-CN.md) · [Документация](README.ru.md)

Сейчас виджеты CanvasTTY — расширения исходного кода, а не runtime-плагины. Это руководство помогает добавить виджет без ослабления изоляции Electron, выдуманной телеметрии и визуального дрейфа.

## Выберите минимальную форму расширения

| Форма | Для чего | Обычный владелец |
|:--|:--|:--|
| Пассивный виджет Home | Часы, launcher, производная подпись или renderer-local представление без собственного wheel-поведения | `features/home/` и чистый selector |
| Виджет Home с main-источником | Использование провайдера, состояние машины или данные, требующие файловой системы, сети, credentials либо subprocess | общий контракт → main service → IPC/preload → чистый selector → компонент Home |
| Сущность канваса | Перемещаемый пространственный объект с мировой позицией, опциональным размером и фокусом | отдельный feature-компонент, собранный в `WorkspaceCanvas` |

Не создавайте main-сервис ради данных, которые уже есть в типизированном состоянии renderer. Не переносите привилегированный запрос в React только потому, что так короче.

## Путь через границы процессов

Для виджета с main-источником двигайтесь в таком порядке:

1. Добавьте очищенный тип запроса/snapshot и имя IPC в [`src/shared/contracts.ts`](../src/shared/contracts.ts).
2. Создайте узкий адаптер или сервис в [`src/main/services/`](../src/main/services/), который владеет credentials, subprocess, timeout, валидацией, кэшем и очисткой ресурсов.
3. Зарегистрируйте один разрешённый handler в [`src/main/ipc/registerIpc.ts`](../src/main/ipc/registerIpc.ts).
4. Откройте только типизированную возможность через [`src/preload/index.ts`](../src/preload/index.ts). Не отдавайте Node-примитивы, сырой IPC, токены, cookies или ответы провайдера.
5. Преобразуйте snapshot в данные представления чистым selector рядом с feature-владельцем.
6. Отрисуйте состояния в узком компоненте и подключите его из Home или `WorkspaceCanvas`.
7. Проверьте нормализацию, ошибки/stale и selector тестами, затем откройте настоящий Electron-сценарий.

`App.tsx` — граница оркестрации. Feature может владеть своей исключительной возможностью, но не должен ходить в API несвязанных features.

## Визуальный язык

Новый виджет должен выглядеть частью CanvasTTY:

- Отталкивайтесь от спокойного пространственного десктопа, а не от панели, забитой контролами.
- Используйте крупные плоские плитки, мягкие радиусы, сдержанные тени и свободные интервалы.
- Графит подходит операционным поверхностям вроде терминалов; sage, розовый, голубой и бледно-жёлтый — спокойным акцентам канваса.
- Делайте подписи короткими, а иерархию — читаемой с первого взгляда и при зуме.
- Оставляйте одно очевидное основное действие. Не добавляйте декоративные status dots, важные hover-only действия, вложенные рамки и поясняющий микротекст вокруг понятных контролов.
- Перехватывайте wheel только когда поверхность действительно скроллится или использует его. Пассивные виджеты Home должны сохранять зум канваса.
- Используйте официальные Lucide SVG из [`assets/icons/lucide`](../src/renderer/src/assets/icons/lucide/) и документированные marks провайдеров из [`assets/providers`](../src/renderer/src/assets/providers/README.md). Не рисуйте иконки в TSX.
- Явно моделируйте `loading`, `available`, `stale`, `unavailable` и `error`. Отсутствие данных нельзя превращать в пустую полоску, ноль или ложный успех.
- Проверяйте обычный масштаб и отдалённую смысловую отрисовку. Одинаковые сущности должны сохранять одинаковые шрифт и насыщенность.

У Home фиксированное владение: media-контролы остаются внутри `HomeMediaWidget`; Settings владеет только языком, палитрой, узором канваса и прилипанием окон. Перед изменением прочитайте [UI-контракт](UI_CONTRACT.md).

## Бриф для другого AI coding agent

Скопируйте его в задачу агента и замените поля в квадратных скобках:

```text
Добавь в CanvasTTY виджет [НАЗВАНИЕ], который показывает [ПОЛЬЗА].

До правок прочитай docs/ARCHITECTURE.md и docs/UI_CONTRACT.md и найди ближайший
существующий feature-паттерн. CanvasTTY — Electron MVP с context isolation:
привилегированная работа остаётся в main, межпроцессные данные объявляются в
src/shared/contracts.ts, IPC разрешается явно, а preload отдаёт только
типизированную очищенную возможность.

Источник: [СТРУКТУРИРОВАННЫЙ ИСТОЧНИК]. Никогда не парси terminal/TUI text и не
выдумывай значения. Рисуй явные loading, available, stale, unavailable и error.
Не отдавай credentials, сырые ответы провайдера, prompts или безграничную историю.

Визуальное направление: спокойный пространственный desktop; крупная плоская
плитка; мягкий радиус; сдержанная тень; графитовые операционные поверхности с
sage/розовыми/голубыми/жёлтыми акцентами; короткие подписи; читаемость при зуме.
Переиспользуй vendored Lucide/provider assets. Не добавляй декоративные точки,
hover-only основные действия, вложенные рамки или собственный SVG в TSX. Сохрани
правила владения wheel.

Scope: [HOME PASSIVE / HOME MAIN-BACKED / CANVAS ENTITY]. Добавь узкие тесты
нормализации и выбора состояния. Запусти npm test, npm run typecheck, npm run
build, затем проверь сценарий в реальном Electron-окне. Не добавляй пакеты.
```

## Пример структуры исходников

Это пример именования, а не runtime ABI плагинов:

```text
src/shared/contracts.ts
src/main/services/SessionUsageService.ts
src/main/ipc/registerIpc.ts
src/preload/index.ts
src/renderer/src/features/session-usage/
├── SessionUsageWidget.tsx
├── sessionUsageModel.ts
└── sessionUsage.css
tests/session-usage.test.mjs
```

Сначала используйте существующие style tokens. Если виджет относится к Home, впишите его в утверждённую логическую композицию, не меняя молча размеры Home и не перенося контролы другого feature.

## Критерии готовности

- Отображаемое значение восходит к названному структурированному источнику.
- Привилегированный доступ остаётся в main; renderer получает очищенные типизированные данные.
- Недоступное, устаревшее и ошибочное чтение различимы.
- У виджета есть ясный владелец; он не дублирует Settings или media-контролы.
- Wheel, focus, drag и canvas zoom не конфликтуют.
- Виджет читается в целевых масштабах и использует существующие assets.
- Нормализация и selector покрыты узкими тестами.
- Проходят `npm test`, `npm run typecheck` и `npm run build`.
- Сценарий проверен в настоящем Electron-окне.
