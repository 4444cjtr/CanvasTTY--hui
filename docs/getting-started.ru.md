# Быстрый старт

[English](getting-started.md) · [Русский](getting-started.ru.md) · [简体中文](getting-started.zh-CN.md) · [Документация](README.ru.md)

## Требования

- Node.js и npm.
- Нативный toolchain для сборки `node-pty`, поддерживаемый на вашей платформе.
- Графическая сессия рабочего стола, в которой можно запустить Electron.
- При необходимости — CLI `codex`, `claude` или `kimi`, установленные и доступные в `PATH` для тех лаунчеров, которыми вы планируете пользоваться.

CanvasTTY не устанавливает CLI агентов и не проходит за вас авторизацию. Сначала выполните штатный вход у самого провайдера — только после этого заработают его сессии и лимиты подписки.

## Установка и запуск

```bash
npm install
npm run dev
```

`npm install` также подготавливает Electron и пересобирает нативный модуль `node-pty`. Команда разработки запускает настоящее Electron-приложение, а не браузерный макет.

## Первая сессия

1. Откройте **Terminal** на Home, чтобы сразу запустить shell в последнем каталоге проекта.
2. Откройте **Codex**, **Claude** или **Kimi**, чтобы выбрать каталог проекта и профиль запуска для этого провайдера (провайдер в диалоге зафиксирован).
3. Откройте **Browser** на Home, чтобы создать или восстановить карточку встроенного браузера. Agent-сессии, запущенные CanvasTTY, могут работать с открытыми вкладками, пока включено **Настройки → Браузер → Доступ агентов**.
4. Перемещайте и меняйте размер живого терминала и браузера на одном канвасе.
5. Отдалитесь, чтобы ориентироваться по смысловым сводкам; приблизьтесь, чтобы работать с xterm или native browser page.
6. Вернитесь на Home, чтобы посмотреть реальные сессии, подключённых browser agents и окна квоты провайдера, которые отдают их адаптеры.

Профиль **YOLO** отключает защитные запросы провайдера там, где провайдер такой режим поддерживает. CanvasTTY показывает явное предупреждение с подтверждением действия; используйте профиль только в каталоге, который вы готовы отдать агенту на изменение.

## Ввод и управление терминалом

- Нажмите на любую живую карточку терминала, чтобы выбрать её. Выбранная карточка сразу получает клавиатурный фокус xterm, поэтому ввод отправляется в PTY без второго клика внутри текстовой области.
- Нажатие по пустому канвасу снимает выбор, клавиатурный фокус и видимую рамку.
- **Настройки → Управление → Автофокус при наведении** выбирает терминал под курсором и снимает выбор после ухода. В обе стороны используется одна задержка: медленно `500ms`, обычно `250ms` или быстро `80ms`. По умолчанию автофокус выключен.
- Направления колеса для прокрутки терминала и зума канваса настраиваются независимо. По умолчанию колесо вниз прокручивает живой терминал вниз, а канвас сохраняет прежнее направление зума CanvasTTY.
- `Shift+Enter` отправляет модифицированный Enter и в совместимых промптах агента вставляет перенос строки без отправки. Обычный `Enter` сохраняет штатное поведение PTY.
- Выделенный текст копируется через `Ctrl+C`/`Ctrl+Shift+C` или `Cmd+C`. Вставка: `Ctrl+Shift+V`, `Cmd+V` или `Shift+Insert`. Обычный `Ctrl+C` без выделения остаётся прерыванием PTY.

## Управление браузером и действия

- Браузер использует те же настроенные click-selection и hover-focus правила, что и terminal cards. Клик по пустому канвасу снимает активное приложение.
- Доверенные tab strip и navigation bar работают с HTTP(S)-страницами. Скрытие карточки сохраняет вкладки; **Закрыть все** удаляет их после подтверждения.
- **Настройки → Браузер** управляют доступом агентов и восстановлением вкладок и показывают недавние загрузки и команды.
- **Очистить данные браузера** удаляет вкладки, site data, cache, auth cache, staged uploads и текущий список загрузок, но намеренно сохраняет постоянный очищенный audit log.
- Журнал находится в Electron `userData/browser/audit`, ротируется при 100 МБ и при инициализации или ротации удаляет ротированные файлы старше 30 дней. Перед ручной обработкой или удалением прочитайте [руководство по браузеру и журналу](browser.ru.md).

## Полезные команды

| Команда | Назначение |
|:--|:--|
| `npm run dev` | Запустить Electron-сборку для разработки |
| `npm test` | Запустить Node-тесты |
| `npm run typecheck` | Проверить типы main/preload и renderer |
| `npm run build` | Проверить типы и собрать production-бандлы |
| `npm run preview` | Запустить собранное приложение для проверки production-сценария |

Перед сдачей изменений выполните тесты, typecheck и build, затем проверьте затронутый сценарий в реальном окне Electron.

## Где хранится локальное состояние

Настройки валидирует и сохраняет `SettingsStore` в main-процессе. Живое состояние терминалов и ограниченный scrollback принадлежат `TerminalManager`; renderer не является источником истины для истории PTY. Site data браузера остаются в постоянном Chromium partition, безопасный restore state — в `userData/browser-state.json`, а очищенный hash-chain audit — в `userData/browser/audit`. Учётные данные провайдеров остаются у установленных CLI и доверенных адаптеров main-процесса и никогда не возвращаются через IPC.

Точные границы описаны в [архитектуре](ARCHITECTURE.ru.md), а правила поведения и внешнего вида — в [UI-контракте](UI_CONTRACT.ru.md).

## Если что-то не работает

### Не собирается `node-pty`

Установите компилятор, Python и системные заголовки для вашей ОС, затем снова выполните `npm install`. Не заменяйте нативный PTY подставным терминалом: работа с реальными локальными процессами — базовое ограничение продукта.

### Агент запускается, но лимиты недоступны

Работающая CLI-сессия и читаемый API квот подписки — это разные возможности. Повторите авторизацию CLI и посмотрите явную причину, которую показывает CanvasTTY. Некоторые типы аккаунтов не отдают окно подписки; интерфейс должен показать недоступность, а не `0%`.

### Терминал открыт, но не отмечен как работающий

Это ожидаемо. Новый PTY стартует в состоянии `idle`. Только структурированный lifecycle-сигнал провайдера может выставить `working` или `needs_approval`; наличие PTY и текст терминала не являются телеметрией активности.
