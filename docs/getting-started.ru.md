# Быстрый старт

[English](getting-started.md) · [Русский](getting-started.ru.md) · [简体中文](getting-started.zh-CN.md) · [Документация](README.ru.md)

## Требования

- Node.js и npm.
- Поддерживаемый вашей системой нативный toolchain для сборки `node-pty`.
- Графическая сессия рабочего стола, в которой запускается Electron.
- При необходимости — CLI `codex`, `claude` или `kimi`, установленные и доступные в `PATH`.

CanvasTTY не устанавливает и не авторизует CLI агентов. До запуска сессий и чтения лимитов пройдите штатную авторизацию самого провайдера.

## Установка и запуск

```bash
npm install
npm run dev
```

`npm install` также подготавливает Electron и пересобирает нативный модуль `node-pty`. Команда разработки запускает настоящее Electron-приложение, а не браузерный макет.

## Первая сессия

1. Нажмите **Terminal** в Home, чтобы сразу открыть shell в последнем каталоге проекта.
2. Нажмите **Codex**, **Claude** или **Kimi**, выберите каталог и профиль запуска для зафиксированного провайдера.
3. Перемещайте живой терминал по канвасу и меняйте его размер за любую грань или угол.
4. Отдалитесь до смысловых карточек для навигации; приблизьтесь для работы с xterm.
5. Вернитесь в Home к реальным сессиям и тем окнам квоты, которые действительно отдаёт адаптер провайдера.

Профиль **YOLO** отключает защитные запросы провайдера там, где такой режим поддерживается. CanvasTTY показывает отдельное предупреждение; используйте профиль только в каталоге, который агенту разрешено изменять.

## Полезные команды

| Команда | Назначение |
|:--|:--|
| `npm run dev` | Запустить Electron-сборку для разработки |
| `npm test` | Запустить Node-тесты |
| `npm run typecheck` | Проверить типы main/preload и renderer |
| `npm run build` | Проверить типы и собрать production-бандлы |
| `npm run preview` | Запустить собранное приложение для production-проверки |

Перед передачей изменений выполните тесты, typecheck и build, затем проверьте затронутый сценарий в реальном окне Electron.

## Где хранится локальное состояние

Настройки валидирует и сохраняет `SettingsStore` в main-процессе. Живое состояние терминалов и ограниченный scrollback принадлежат `TerminalManager`; renderer не является источником истины для истории PTY. Credentials остаются у установленных CLI и доверенных адаптеров main-процесса и никогда не возвращаются через IPC.

Точные границы описаны в [архитектуре](ARCHITECTURE.md), а правила поведения и внешнего вида — в [UI-контракте](UI_CONTRACT.md).

## Если что-то не работает

### Не собирается `node-pty`

Установите компилятор, Python и системные headers для вашей ОС, затем снова выполните `npm install`. Не заменяйте нативный PTY фальшивым терминалом: реальные локальные процессы — базовое ограничение продукта.

### Агент запускается, но лимиты недоступны

Работающая CLI-сессия и доступное API лимитов подписки — разные возможности. Повторите авторизацию CLI и посмотрите явную причину в CanvasTTY. Некоторые типы аккаунтов не отдают окно подписки; интерфейс должен показать недоступность, а не `0%`.

### Терминал открыт, но не отмечен как работающий

Это ожидаемо. Новый PTY начинается в состоянии `idle`. Только структурированный lifecycle-сигнал провайдера может выставить `working` или `needs_approval`; наличие PTY и текст терминала не являются телеметрией активности.
